Spotify Explicit Content & Track Characteristics

Exploring explicit-content labels, track durations, and release dates using data collected through the Spotify Web API.

01 · Overview

Project Summary

Streaming platforms contain extensive metadata about recorded music. This project uses Spotify track-level data to explore patterns in explicit-content labels and other available characteristics.

I collected a sample of 50 tracks across five search-term groups and used Python to organize, summarize, and visualize the results.

The goal was exploratory rather than predictive: to understand the sampled tracks and identify questions worth investigating with a larger, more representative dataset.

02 · Research Questions

What I Wanted to Explore

  • How frequently are tracks marked explicit within the collected sample?
  • How do track durations vary across the sample?
  • What does the distribution of release dates reveal about the tracks returned by the searches?
  • What limitations affect conclusions drawn from Spotify API search results?

03 · Data Collection

Source & Methodology

Data Source

Spotify Web API search results, collected using Python.

50 tracks · 5 search-term groups

Analysis Workflow

Retrieved track metadata, organized records into a pandas DataFrame, examined available fields, and generated exploratory summaries and visualizations.

04 · Analysis

Track Characteristics

The analysis focuses on the information available in the collected track metadata.

Explicit-Content Labels

Compared the presence of Spotify's explicit-content flag among sampled tracks. The flag identifies Spotify's content classification; it does not independently measure lyrical themes or severity.

Track Duration

Examined duration values to understand variation in song length within the sample.

Release Dates

Reviewed available release-date metadata to explore the age distribution of the sampled recordings.

Search Sampling

Considered how search terms and API results influence which tracks appear in the dataset.

05 · Interpretation

What the Analysis Demonstrates

This project demonstrates an end-to-end exploratory workflow: obtaining data from an external API, preparing a structured dataset, examining distributions, and communicating limitations.

Because the dataset contains only 50 tracks returned from selected search terms, its descriptive results should not be interpreted as representative of Spotify's full catalog.

Popularity scores were not available in the collected data because of API access restrictions. Consequently, this project does not establish a relationship between explicit content and track popularity.

06 · Limitations

Important Considerations

  • Small sample size limits generalizability.
  • Search-term selection introduces sampling bias.
  • Spotify's explicit-content flag is a categorical metadata field, not a direct measure of lyrical content.
  • Popularity data was unavailable, preventing a valid popularity comparison.
  • Results describe this sample rather than establishing causal relationships.
